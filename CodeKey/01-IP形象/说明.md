# 01 · IP 形象

品牌资产，**只增不改**。这里的内容一旦发布到读者面前就不要再变，否则 IP 认知会漂移。

## 计划迁入

把现在的 `../微信表情包/` 整体移进来，重命名为 `猴米_表情包/`：

```
01-IP形象/
├── 猴米_表情包/
│   ├── 打工小猴/       24 张
│   ├── 猴米懂礼貌/     19 张
│   └── 猴米上学记/     20 张
├── 头像与二维码/
│   └── 公众号二维码.png
└── 品牌规范.md
```

根目录那 2 张散落图（`222222-a370-…`、`23232323-5fe9…`）需要你目视确认属于哪一套，再手工归位。

## 迁移步骤（顺序不能反）

重命名脚本的工作目录写死在 `微信表情包/`，**必须先跑脚本、后搬目录**：

```bash
# 1. 先预览，确认要改哪些
node CodeKey/06-运营方案/tools/rename-assets.mjs

# 2. 去掉 uuid，改成纯序号 001.png
node CodeKey/06-运营方案/tools/rename-assets.mjs --apply

# 3. 打开 06-运营方案/命名对照表.md 填语义名，然后落地
node CodeKey/06-运营方案/tools/rename-assets.mjs --apply --semantic

# 4. 最后搬目录 —— 用 git mv，不要用文件管理器拖拽
#    （拖拽在 git 眼里是「删除 + 新增」，会丢掉重命名历史）
git mv "CodeKey/微信表情包" "CodeKey/01-IP形象/猴米_表情包"
```

如果先搬了目录，脚本会报「找不到表情包目录」——改脚本顶部的 `STICKER_ROOT` 即可。

## 命名规范

`<三位序号>-<语义名>.png`，如 `001-摸鱼.png`。序号**每套独立**从 001 开始
（微信表情开放平台是按套提交的）。

语义名只写中文/英文/数字，不要带 `-`、`/`、空格。

## 用途

| 用途 | 说明 |
| --- | --- |
| 上架表情开放平台 | 三套可独立提交，作者页是公域涨粉入口 |
| 正文插图 | 「小猴点评」前放一张对应情绪的表情包做视觉标点 |
| 封面元素 | 三套封面模板里的固定小猴形象 |
| 文末钩子 | 「回复【猴米】领取全套表情包」 |
