# 历史人物志 · A + B 结合方案

> 2026-10-21 ｜ 账号：程序小猴 ｜ 关联：`栏目规划_2026-10-21.md`
> 背景：9-21 定案时这一栏被否过（稀释垂直度）。今天你选了 A+B 结合，那就把它做成
> **不破垂直度、不占主力群发位、还能给你验证需求**的一套东西。

---

## 0. 一句话

**贴图给结论，文章给方法。** 贴图是低成本试错器，文章是方法沉淀；两条同属一个合集，
都不占主力群发位。

先把名字改一下。「历史人物志」暗示纯人物传记，跟你实际要做的内容对不上，
而且「历史」这个赛道红海得没边。**合集名建议用「史书里的数据」**——
它同时告诉算法和读者：这是数据活儿，不是讲故事。

---

## 1. 为什么必须 A+B，不能只选一个

只做 A（技术交叉文），问题是没有曝光入口。技术文本来就起量慢，再叠一个冷门题材，
可能发三篇都没人看见，你也不知道是题材不行还是方法不行。

只做 B（贴图），问题是留不住人。贴图是公域流量，看完即走，
而且**没有原创按钮**，搜一搜「声明原创优先」这条优势直接失效，赚不到沉淀。

合起来才成闭环：

```text
贴图（B）            文章（A）
一个数据点            完整实现过程
视觉冲击 → 被看见     技术细节 → 被收藏
    ↓                    ↓
 测出需求             沉淀方法
    └──── 同属「史书里的数据」合集 ────┘
```

贴图跑出来的数据，直接决定文章要不要写——**这是这套方案最值钱的地方**。

## 2. 栏目设定

| | 贴图（B 线） | 文章（A 线） |
| --- | --- | --- |
| 形式 | 图片消息，3:4（1080×1440），2~4 张 + 200 字内短文 | 图文，1600~2200 字 |
| 定位 | 前端测试 + 引流 | 方法沉淀 + 搜索入口 |
| 占群发位 | ❌ 不占 | ✅ 占「技术实操」的一个位置 |
| 通知粉丝 | ❌ 不通知（这点很重要，不打扰现有 245 人） | ✅ 正常群发 |
| 流量来源 | 贴图独立推荐池 | 搜一搜 + 合集内跳转 |
| 频率 | 2~3 周 1 条 | 3~4 周 1 篇，**看贴图数据再决定写不写** |
| 搜索词 | 无（不指望） | Python / pandas / matplotlib / Obsidian |

贴图规格（2026-10-21 查证）：最多 20 图 + 1000 字，**首图决定点击率**，
标题 ≤64 字、建议 20 字内。

---

## 3. 分工必须切干净，不许撞题

这是 A+B 最容易做砸的地方——同一条内容两边都发一遍，读者看两次，两边都没价值。

| | 贴图只发这个 | 文章只发这个 |
| --- | --- | --- |
| 内容 | **结论**：关羽换算过来 2.07 米 | **方法**：这个数从《三国志》原文到 Excel 再到图表，中间怎么清洗的 |
| 读者拿走什么 | 「原来是这个数」 | 「我也能做出来」 |
| 标题长什么样 | 三国武将身高换算，最高的不是关羽 | 用 Python 把《三国志》里的人物身高算出来，我踩了三个坑 |
| 什么时候发 | 先发 | 后发，文里可以引用「上一条贴图有人问数据哪来的」 |

一句话记住：**贴图负责「哇」，文章负责「怎么做的」。**

## 4. 选题清单

### B 线 · 贴图选题（5 条，按推荐度排）

筛选标准：单点、有反差、能画成一张图、不需要读者有历史基础。

| # | 选题 | 为什么能做 | 图怎么做 |
| --- | --- | --- | --- |
| B01 | 三国武将身高换算成现在是多少 | 有具体数字，天然反差（古人普遍偏高？）| 横向条形图 + 人物剪影 |
| B02 | 古代一两银子值现在多少钱 | 「值多少」是所有人心里的疑问 | 朝代轴 + 购买力折算 |
| B03 | 二十四史里出现最多的十个名字 | 排名自带传播力 | 排行榜长图 |
| B04 | 历代皇帝的平均寿命 | 结论反直觉（比想的短） | 折线 + 均值线 |
| B05 | 《水浒》108 将的籍贯分布 | 地域话题容易引发讨论 | 地图 + 热力配色 |

> **第一条建议做 B01。** 它最符合三个条件：数字具体、反差明显、一张图能讲完。
> 而且「三国」是这个题材里认知门槛最低的入口。

### A 线 · 文章选题（5 条，等贴图数据再定先写哪篇）

筛选标准：有真实技术过程、有一手踩坑、标题能放技术词。

| # | 选题 | 目标搜索词 | 难度 |
| --- | --- | --- | --- |
| A01 | 用 Python 统计《三国演义》谁出场最多 | Python 文本分析、jieba 分词 | 中 |
| A02 | 二十四史人物词频，我用 pandas 跑了 3000 万字 | pandas 词频、中文分词 | 高（数据清洗量大） |
| A03 | 用 Obsidian 建三国人物关系图谱 | Obsidian 关系图谱、知识管理 | 低 |
| A04 | 历史人物生卒年，我用一张时间轴看完了两千年 | matplotlib 时间轴 | 中 |
| A05 | 《红楼梦》前 80 回和后 40 回，用词差在哪 | 文本相似度、余弦相似度 | 中 |

> A03 难度最低，适合当第一篇 A 线稿的试水——不用处理大数据，出图快。
> A02 最有可能出圈（3000 万字这个数字有冲击力），但要先解决数据源。

## 5. 第一条怎么做（B01，具体到物料）

**标题**（20 字内，首图定生死）：

- 首选：`三国武将身高换算，最高的不是关羽`
- 备选：`关羽 2.07 米？三国武将身高换算成现在`

**内容结构（3 张图）**

| 图 | 内容 |
| --- | --- |
| 第 1 张（首图） | 一张对比图：五个武将横向条形，最高的那条标红。**不做文字堆砌，让图自己说话** |
| 第 2 张 | 换算方法：汉尺换算成厘米的两种说法，取哪一版、为什么 |
| 第 3 张 | 数据来源与出处清单（书名 + 篇目），标清楚哪几个数是估算 |

**正文（150~200 字）**

只说三件事：数据从哪来、换算用的什么标准、哪几个数不可靠。
**不做人物评价，不写故事。**

**物料清单**

| 物料 | 规格 | 备注 |
| --- | --- | --- |
| 三张图 | 1080×1440，3:4 | 首图主体居中，别贴边 |
| 标题 | ≤20 字 | 发的时候用 |
| 正文 | ≤1000 字，实际 200 字足够 | 微信贴图允许 1000 字，但没人看长文 |
| 来源标注 | 每张图右下角 | 史实可信度是人设保险 |

## 6. 实验判据（写死，别凭感觉）

**时间点**：11 月中发第一条，连发 3 条，12 月初看数据。中间不要因为「感觉没量」就停。

| 判据 | 达标 | 不达标怎么办 |
| --- | --- | --- |
| 单条 30 天阅读 | 3 条里有 1 条 **> 300**（接近工具文量级） | 全在 100 以下 → 题材在你读者里没需求，停 |
| 推荐流 | 30 天内推荐来源 **> 8 次**（当前全站基线） | 一直是个位数 → 算法不认这类内容，停 |
| 新增关注 | 至少 1 条带来关注 | 阅读有量、关注为 0 → 只当流量实验，不做栏目 |
| 收藏 | 有收藏 | 0 收藏 → 内容不构成"资产"，A 线文章也别写 |

**四种结果对应的动作**

1. 三项都达标 → 升为正式栏目，A 线固定每 3 周 1 篇
2. 阅读达标、关注为 0 → 保留贴图做流量实验，A 线暂缓
3. 阅读不达标、推荐有量 → 内容方向对但选题偏，换选题再试 3 条
4. 全不达标 → **停，别硬撑**。你已经花了两周验证，这比闷头做半年强

## 7. 红线

| 红线 | 说明 |
| --- | --- |
| **史实必须能溯源** | 每个数字标出处（书名 + 篇目）。写错一次，「实测」人设就废，这是本号唯一资产 |
| **不做人物评价** | 只摆数据，不评判历史人物。评价必然引战，且没有搜索价值 |
| **避开近现代史** | 古代史相对安全。近现代人物、政治评价、民族议题一律不碰 |
| **不占主力群发位** | 贴图本来就不占；A 线文章占的是「技术实操」的位子，不能挤掉工具实测 |
| **不用网图** | 图表自己做，既避版权风险，也保证和图注一致 |
| **不因贴图影响主号节奏** | 主力是技术实操 + 工具实测，历史这条线永远是实验位 |

## 9. 和主号的关系

`栏目规划_2026-10-21.md` 里的 4 个栏目不变，这一栏永远是第 4 个，排在最后。

两条硬边界：

1. **贴图永远不占群发位。** 群发位必须先喂饱技术实操和工具实测。
