# RS-485 详解：工业现场为什么这么喜欢这两根线？

> 🐵 程序小猴 · 嵌入式通信协议系列 Vol.03

---

如果你做工业自动化，RS-485 几乎绕不开。

PLC、变频器、温控器、称重模块、传感器......设备背后经常就两个端子：

``` text
A
B
```

看起来平平无奇。

但就是这两根线，可以在复杂工业环境里连接一串设备。

## 一、RS-485 最核心的秘密：差分

单端通信关心的是：

``` text
信号线相对于 GND 是多少伏？
```

差分通信更关心：

``` text
A 和 B 之间相差多少？
```

假设干扰同时耦合到两根线上：

``` text
A：+1V 干扰
B：+1V 干扰
```

两者差值变化并没有那么大。

这就是差分传输抗共模干扰能力较强的重要原因。

## 二、RS-485 不等于 Modbus

这两个经常被混淆。

可以这样理解：

``` text
Modbus RTU
    ↓
UART数据
    ↓
RS-485收发器
    ↓
A/B双绞线
```

RS-485主要解决物理层传输。

至于线上跑什么数据，可以是：

-   Modbus RTU；
-   自定义协议；
-   其他串行协议。

## 三、为什么能挂很多设备？

典型结构：

``` text
      ┌── Node 1
Master├── Node 2
A/B===├── Node 3
      └── Node 4
```

但要注意：

**RS-485 本身不会自动帮你解决"谁什么时候说话"。**

多节点协议必须规定：

-   地址；
-   主从关系；
-   发送时机；
-   超时；
-   冲突处理。

这也是 Modbus RTU 经常和 RS-485 一起出现的原因。

## 四、半双工为什么要控制 DE/RE？

常见 RS-485 收发器有：

``` text
DI
RO
DE
/RE
```

发送时：

``` text
DE = 1
```

发送完成后：

``` text
DE = 0
```

问题来了。

什么时候算"发送完成"？

不是把最后一个字节写进 UART 数据寄存器就算结束。

因为最后几个 bit 可能还在移位寄存器里往外发送。

如果 DE 提前关闭：

``` text
最后一个字节：0x5?
```

帧尾就可能直接被切掉。

这类 bug 非常隐蔽。

## 五、120Ω 终端电阻到底干什么？

长线可以看成传输线。

信号到达线缆末端，如果阻抗不匹配，就可能发生反射。

表现到示波器上可能是：

``` text
理想：
____|‾‾‾‾‾‾

反射明显：
____|‾\_/‾\__
```

因此 RS-485 总线通常在线路**两端**配置匹配终端。

注意是总线两端，不是每一个节点都放 120Ω。

## 六、为什么不推荐星形布线？

理想结构更接近：

``` text
Node ─── Node ─── Node ─── Node
```

而不是：

``` text
          ┌── Node
Master ───┼── Node
          ├── Node
          └── Node
```

星形分支会产生多个传输线支路，容易引入反射。

低速、短距离时可能"怎么接都能跑"，速度和距离上去后问题就出现了。

## 七、A/B 到底谁正谁负？

这是 RS-485 世界一个很烦人的历史问题。

不同厂商对 A/B 标识可能存在差异。

所以现场不要只凭"A 对 A、B 对 B"的直觉。

最可靠的是：

**看芯片数据手册、设备说明书，并用示波器确认。**

## 八、工程上还要考虑隔离

工业现场两台设备可能：

-   供电系统不同；
-   地电位不同；
-   距离很远；
-   附近存在大功率设备。

因此比较可靠的设计经常是：

``` text
MCU
 ↓
数字隔离
 ↓
隔离型RS-485收发器
 ↓
TVS / 防护
 ↓
A/B
```

这已经不仅仅是"通信协议"的问题，而是 EMC、浪涌和系统可靠性设计。

## 九、RS-485 出问题怎么查？

推荐顺序：

``` text
① UART原始数据对不对？
        ↓
② DE方向控制对不对？
        ↓
③ A/B差分波形对不对？
        ↓
④ 终端和拓扑对不对？
        ↓
⑤ 协议帧和CRC对不对？
```

一层一层排查，比直接盯着 Modbus 程序有效得多。

## 工程实战：一条线挂多台设备

设主站轮询四台从站，四台都使用 UART 9600、8N1、RS-485 半双工。主站先使能驱动器 DE，发送完请求后要等待**最后一个停止位真正离开发送移位寄存器**，再关闭 DE 并转入接收；只等 TX 数据寄存器空，最后一个字节可能被截断。从站只能在收到属于自己的完整请求后应答，并设置超时和响应间隔。RS-485 本身并不规定地址、校验或轮询顺序，这些是上层协议的工作。

接线检查按顺序做：确认共用参考地方案及隔离边界；只在总线**两个物理端点**设置与线缆特性阻抗匹配的终端，常见为 120 Ω；核对空闲偏置由谁提供；尽量使用总线拓扑，缩短支线。两只 120 Ω 终端并联时，断电测 A/B 间电阻常接近 60 Ω，但偏置电阻、芯片和其他并联路径会影响读数，不能单靠这一项判定接线正确。

所谓 A/B 对应正负在不同芯片资料中标法可能相反。以收发器数据手册定义和实际空闲、发送差分波形为准。现场偶发 CRC 错误时，记录错误是否与电机启动同步，再分别检查终端、接地、共模范围、波特率与 DE 切换时间。
