# RS-232：那个看起来"过时"，却一直没有消失的串口

> 🐵 程序小猴 · 嵌入式通信协议系列 Vol.02

---

如果你拆过老式工控机、仪器仪表、PLC
或数控设备，大概率见过一个九针接口：**DB9**。

它背后经常就是 RS-232。

USB 已经如此普及，为什么 RS-232 还活着？

答案其实很工程：**简单、成熟、够用。**

## 一、UART 和 RS-232 别再混为一谈

MCU 内部 UART 输出的是逻辑电平，而 RS-232 使用另一套电气标准。

因此通常需要：

``` text
MCU UART
   ↓
MAX3232
   ↓
RS-232
   ↓
DB9
```

MAX3232 这类芯片做的事情，本质上就是电平转换。

## 二、RS-232 有个很反直觉的地方

TTL UART 通常：

``` text
高电平 = 1
低电平 = 0
```

RS-232 的电压和逻辑定义却不同，而且使用正负电压表示状态。

所以：

> 千万不要把 MCU 的 UART 引脚直接接到真正的 RS-232 接口上。

## 三、为什么以前电脑特别喜欢它？

因为它特别适合：

``` text
PC ↔ 单台设备
```

不需要复杂网络，不需要地址管理，配置好波特率就能收发。

在调试设备、配置仪器、输出日志这些场景里，它至今依然很好用。

## 四、它的短板也很明显

RS-232 使用单端信号。

当线缆变长、现场干扰变强时，它的优势迅速下降。

因此工业现场如果要跑几十米甚至更远，工程师通常会想到另一个名字：

**RS-485。**

## 五、DB9 不等于 RS-232

这也是常见误区。

DB9 只是连接器形式。

同一个 DB9 外壳里面完全可能接：

-   RS-232；
-   RS-485；
-   CAN；
-   厂商自定义信号。

看到 DB9，不能闭眼就插。

先看设备说明书和引脚定义。

## 六、什么时候今天仍然值得用 RS-232？

如果需求是：

-   点对点；
-   距离不长；
-   速度要求不高；
-   环境相对稳定；
-   希望调试方便；

RS-232 完全可以继续用。

工程设计不是追求"最新"，而是选**复杂度最低且能可靠满足需求**的方案。

---

## 一次常见的接线误会

MCU 的 UART TX 空闲通常为逻辑高，而传统 RS-232 的电压极性与电压范围不同。直接把 MCU 引脚接 DB9 的 RX，轻则收不到，重则损坏引脚；应通过合适的 RS-232 收发器转换。连接两台设备时还要确认两端是 DTE 还是 DCE，核对 TX、RX、GND 的针脚定义；同是 DB9 外形，并不保证同一电气标准或针脚功能。

排查顺序：先在 MCU 引脚确认 UART 波形，再在转换器线侧确认电压摆幅和反相，最后检查线缆与对端参数。串口工具显示乱码时也别直接判断“转换芯片坏了”，先核对波特率、数据位、校验位、停止位及流控。
