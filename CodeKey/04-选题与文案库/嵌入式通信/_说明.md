# 嵌入式通信

**这个文件夹放什么、怎么用。**

对应公众号「程序小猴」的 **嵌入式通信避坑** 系列素材，目标是一个可长期被搜到的技术系列
（规划见 `_系列规划.md`）。

## 目录结构

```
嵌入式通信/
├── _说明.md              ← 本文件，先看这个
├── _系列规划.md          ← 系列结构、标题库、技术红线、发布节奏
├── 素材原稿/             ← 13 篇协议原稿（素材，只作参考底本）
└── 推文成稿/             ← 实际要发布的推文（改造后的成品）
```

**为什么要分「原稿 / 成稿」两层**：原稿是知识体系（按协议分类），
成稿是故障入口（按读者会搜的问题分类）。两者内容有交集但定位完全不同，
混在一层，三个月后就分不清哪份是能发的那份。
（这条规矩的教训来自 `../../05-栏目素材/说明.md`：素材和定稿不要混着放。）

## 使用规则

1. **写作时以 `素材原稿/` 为知识底本，但不要直接搬运。**
   原稿是「协议轴」，标题写成「XX 详解」搜不到人。
   改造成「故障轴」，标题带具体现象和芯片名，改造公式见 `_系列规划.md` 第 2 节。
2. **技术事实以厂商手册为准，不以原稿为准。** 原稿经过核对，但仍有 2 处需修
   （CAN 未讲标准帧优先于扩展帧、1-Wire 单线多设备），清单在规划的「红线」一节。
3. **每篇成稿必须补一手经历。** 原稿最大的短板是一处现场经历都没有，
   这是本号「选题四问」的第三问，也是唯一抄不走的部分。文里用 `[📝]` 标了位置。
4. **发布后的定稿**按 `05-栏目素材/说明.md` 的命名规则（`<日期>_<关键词>.md`）
   归到 `05-栏目素材/技术干货/2026-XX/`，不要留在本目录。
