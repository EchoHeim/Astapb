## 五条约定

1. **编号前缀（01–05）不要改。** 数字前缀在文件管理器、GitHub、命令行里的排序都稳定；
   换成中文名开头排序，Windows 与 macOS 结果不一致。
2. **`AI 日报/` 不在编号里，是有原因的，别顺手挪进 03。**
   博客的 `WebBlog/scripts/sync-ai-brief.mjs` 在构建前直接读这个路径生成「AI 简报」；
   `.github/workflows/publish.yml` 的 `paths-ignore` 也因此**故意没有**列它。
   一旦挪进编号目录，日报改动就不再触发构建，线上简报会**静默停更且没有任何报错**。
3. **方法论与成稿分层。** 03 的根层放方法论（选题池/标题库/金句库/固定模块），
   成稿按栏目进子目录。混放的后果是同一素材出现多个版本，三个月后分不清哪个是终稿。
4. **03 是核心，先维护它。** 图片是一次性消耗品，选题库和数据表才是复利资产。
5. **发文前跑一次查重、发完立刻登记并回填数据。** 9 月已经出现过两对同主题重复推送，
   其中一对是两个不同标题的同一主题——肉眼看不出来，靠 `05-发布登记` 拦：
   `node CodeKey/05-发布登记/check-publish.mjs "候选标题" --topic=xxx --date=YYYY-MM-DD`

## 使用须知

### 中文路径

仓库里有中文目录与文件名。在 Windows 上建议先执行：

```bash
git config core.quotepath false
```

否则 `git status` / `git log` 会把中文路径显示成 `\346\226\207...` 转义序列。
通过 GitHub 网页或 CDN 访问这类路径时，需要做 URL 编码。

### 体积

图片素材累计约 **17 MB**，目前无压力。但请注意：

- GitHub **单个文件超过 100 MB 会被直接拒绝**；
- 仓库总体积已接近建议上限（`.git` 约 357 MB），素材持续增长会加速逼近；
- **一旦提交进 git，就只能靠重写历史来回收空间**，删文件不会让仓库变小；
- 若素材会持续变大，更合适的位置是独立私有仓库或对象存储，而不是主仓库。

### AI 日报的版权

日报是**二次创作**。发布时必须做到：保留「仅代表个人观点」与来源声明、
不整段搬运原文、**原创点评的篇幅占到该条内容一半以上**。
「小猴点评」才是作品本体，新闻本身不是。
