## 四条约定

1. **编号前缀（01–07）不要改。** 数字前缀在文件管理器、GitHub、命令行里的排序都稳定；
   换成中文名开头排序，Windows 与 macOS 结果不一致。
2. **素材与定稿分离。** 01–03 存可复用素材，05 存已发布定稿。
   混放的后果是同一素材出现多个版本，三个月后分不清哪个是终稿。
3. **04 是核心，先维护它。** 图片是一次性消耗品，选题库和数据表才是复利资产。
4. **发文前跑一次查重、发完立刻登记。** 9 月已经出现过两对同主题重复推送，
   其中一对是两个不同标题的同一主题——肉眼看不出来，靠 `07-发布登记` 拦：
   `node CodeKey/07-发布登记/check-publish.mjs "候选标题" --topic=xxx --date=YYYY-MM-DD`

## 待办：把表情包迁入 01-IP形象

`微信表情包/` 现在仍在根目录，需要迁到 `01-IP形象/猴米_表情包/`。

**顺序不能反** —— 重命名脚本的工作目录写死在 `微信表情包/`：

```bash
# 1. 预览改名计划（不改文件）
node CodeKey/06-运营方案/tools/rename-assets.mjs

# 2. 去掉 uuid，改成纯序号 001.png（每套独立编号）
node CodeKey/06-运营方案/tools/rename-assets.mjs --apply

# 3. 在 06-运营方案/命名对照表.md 里填语义名，然后落地为 001-摸鱼.png
node CodeKey/06-运营方案/tools/rename-assets.mjs --apply --semantic

# 4. 用 git mv 搬目录（文件管理器拖拽会丢掉 git 的重命名历史）
git mv "CodeKey/微信表情包" "CodeKey/01-IP形象/猴米_表情包"
```

若先搬了目录，脚本会报「找不到表情包目录」——改脚本顶部的 `STICKER_ROOT` 即可。

### 命名规范

`<三位序号>-<语义名>.png`，如 `001-摸鱼.png`。序号**每套独立**从 001 开始
（微信表情开放平台是按套提交的）。语义名只写中文/英文/数字，不带 `-`、`/`、空格。

散落在根目录的 2 张图（`222222-a370-…`、`23232323-5fe9…`）脚本不动它们，
需目视确认属于哪一套后手工归位。

## 使用须知

### 中文路径

仓库里有中文目录与文件名。在 Windows 上建议先执行：

```bash
git config core.quotepath false
```

否则 `git status` / `git log` 会把中文路径显示成 `\346\226\207...` 转义序列。
通过 GitHub 网页或 CDN 访问这类路径时，需要做 URL 编码。

### 体积

图片素材累计约 **17 MB**，目前无压力。但请注意：

- GitHub **单个文件超过 100 MB 会被直接拒绝**；
- 仓库总体积已接近建议上限（`.git` 约 357 MB），素材持续增长会加速逼近；
- **一旦提交进 git，就只能靠重写历史来回收空间**，删文件不会让仓库变小；
- 若素材会持续变大，更合适的位置是独立私有仓库或对象存储，而不是主仓库。

### AI 日报的版权

日报是**二次创作**。发布时必须做到：保留「仅代表个人观点」与来源声明、
不整段搬运原文、**原创点评的篇幅占到该条内容一半以上**。
「小猴点评」才是作品本体，新闻本身不是。
