# 往期数据表 · 字段说明

配套文件：`往期数据.csv`

**这是整个素材库里唯一能让你「下一篇比上一篇好」的东西。**
没有数据回填，所有优化都是猜——你只能凭感觉判断哪个标题好，而感觉通常不准。

---

## 字段定义

列的结构与公众号后台「内容分析 → 已发表文章」列表**一一对应**，抄起来不用换算。

| 列  | 字段         | 来源     | 说明                                             |
| --- | ------------ | -------- | ------------------------------------------------ |
| A   | 发布日期     | 后台     | `YYYY-MM-DD`                                     |
| B   | 栏目         | 手填     | `工具实测` / `AI日报` / `拆代码` / `其他`        |
| C   | 标题         | 后台     | 保留原文，方便复盘标题模式                       |
| D   | 标题类型     | 手填     | 数字型 / 疑问型 / 结论型 / 热点型 / 对比型，见下 |
| E   | 阅读人数     | 后台     | 内容分析列表里的「阅读人数」                     |
| F   | 分享人数     | 后台     | 注意是「人数」不是「次数」                       |
| G   | 新增关注人数 | 后台     | **判断「拉新能力」的关键指标**                   |
| H   | 送达阅读率   | 后台     | 后台直接给，就是打开率                           |
| I   | 阅读完成率   | 后台     | 低于 50% 说明文章太长或开头没抓住人              |
| J   | 分享率       | **公式** | `=F{行}/E{行}`，即 分享人数 ÷ 阅读人数           |
| K   | 备注         | 手填     | 状态标记 + 异常情况，口径见下                    |

> **前 9 列全部来自后台，只有「标题类型」和「备注」需要你判断。**

## 标题类型分类（D 列）

统一只用这五种，否则统计不出来：

| 类型     | 特征                | 例                                       |
| -------- | ------------------- | ---------------------------------------- |
| `数字型` | 含具体数字          | 「我用 3 条命令定位到根因」              |
| `疑问型` | 用问句提问题        | 「板子插 U 盘总要手动挂载？」            |
| `结论型` | 直接给判断          | 「struct 和 class 的区别不止是默认权限」 |
| `热点型` | 含具体新闻主体      | 「腾讯 WorkBuddy 联手 DeepSeek」         |
| `对比型` | 试了 N 种最后选了 X | 「试了三种方案最后选了 Samba」           |

## 健康参考值

| 指标       | 健康线                      | 偏低说明                                 |
| ---------- | --------------------------- | ---------------------------------------- |
| 送达阅读率 | ≥ 8%（老号）／≥ 15%（新号） | 标题、封面、账号定位，或粉丝本身已沉睡   |
| 阅读完成率 | ≥ 50%                       | 文章太长、开头没钩子、或内容不是读者要的 |
| 分享率     | ≥ 1.5%                      | 内容不实用、不共鸣，或转发出去「没面子」 |
| 新增关注   | ≥ 阅读人数的 1%             | 文末没有涨粉钩子                         |

## 使用节奏（2026-10-21 起：改为月度批量回填）

**不再逐篇回填，改为每月导出一次、批量写入。**

为什么改：这是搜索型账号，工具文是**爬坡型**（排名慢慢往上爬，14 天才大致定型，个别更长），
7 天值本身就系统性偏低；再加上逐篇抄写的执行成本高，实际结果是**断更**——
9 月下旬断过两次，10-09 之后整整一批日报没回填，台账落后现实两周，等于没有数据。
月度导出一次拿全 30 天，既更准又更省事。

> **三个注意点（不变）**
> - 打开率列（H）填后台给的「送达阅读率」原值，**不要自己换算**——
>   截图里的百分比换算出来的送达基数明显不一致，自己算是错的。
> - 分享率列（J）是公式，新增行请复制上一行。
> - 文件是 UTF-8 with BOM，Excel 直接双击打开中文不乱码，**不要另存为 ANSI**。

### 口径统一：只认「满 30 天累计值」

列里的数字必须是同一个口径，否则平均阅读、栏目对比全是错的。
现有这份表已经混了四种口径（7 天值 / 24h 值 / 后台 30 天聚合 / 未满 7 天快照），
**从本月起统一按「发布后满 30 天的累计值」记**：

| 行状态 | 判定                   | 处理                                                         |
| ------ | ---------------------- | ------------------------------------------------------------ |
| 已成熟 | 发布日距今 ≥ 30 天     | 数值锁定不再改，备注写 `30d终值`                             |
| 未成熟 | 发布日距今 < 30 天     | 先按导出值填，备注写 `WIP-{N}d`，**下个月重刷一次**          |
| 无数据 | 后台列表里根本没有这篇 | 备注写 `未发出`（或 `已删除`），阅读填 0，**别再靠猜补数**   |

### 每月固定动作（建议每月 1 日）

1. 后台「内容分析 → 已发表文章」选**最近 30 天**，导出。
   或「数据 → 内容分析 → 导出」拿 `tendency_*.xls`（含渠道趋势、单篇来源）。
2. 交给 AI 解析入库（`tendency_*.xls` 是真 BIFF8，`user_analysis.xls` 是 HTML 伪装的，两条解析路径都已验证过）。
3. 回填三件事，顺序别错：
   - **补新行**：窗口里还没登记的发文；
   - **重刷 WIP**：上个月标了 `WIP-*` 的行换成新值；
   - **标题对齐**：一律抄后台「已发表文章」列表的标题，**不要抄本地文件的 H1**
     （10-09 已实证：10/1、9/28、9/29 三处本地标题与后台都对不上）。
4. 做一次复盘：按栏目分组算平均阅读与完成率，TOP3 和倒数 3 各写一句「它们有什么不同」。

### 数据月更 ≠ 发稿检查月更

回填可以一个月一次，但**下面两个动作必须每篇都做，且零成本**：

- 发布前跑 `check-publish.mjs`（同日同平台 / 主题标识 / 标题 bigram / 关键词 / 实体重合）。
- 手动 Read 最近 3 天日报，逐条对实体——脚本对短实体（骁龙、千问）会漏报。

这两个动作**不依赖后台数据**，只看登记表和近期稿件。把它们连带着一起停掉，
就会出现「一个月内连写三个同实体选题，月底复盘才发现全扑」。

## 历史复盘结论（2026-09 数据，仍成立）

回填至 2026-09-21 的第一批 22 条数据，已得出两条硬结论：

1. **工具实测 7 篇 = 378 阅读（占 83%），AI 日报 13 篇 = 68 阅读（占 15%）** —— 产能和产出完全倒挂。
2. **全站 69.6% 的阅读来自搜一搜**，粉丝推送只占 11.9%（227 粉 × 0.44% ≈ 每篇 1 人）。
   → 这是一条**搜索型**账号，选题的第一标准是「有人会去搜」，不是「今天什么热」。

> ⚠️ 已撤回的结论：「带版本号标题赢 63 倍」「新格式赢 73%」「完成率 57~75% 是健康线」
> —— 都是小分母 / 混淆变量的产物，别再用。

完整分析与行动方案见 `../../04-运营方案/运营方案_v2_搜索优先_2026-09-21.html`（**结论以 v2 为准**）。

## 从后台导出的最快路径

公众号后台 → 左侧「内容分析」→ 已发表文章列表 → 选时间范围（最近 30 天）。
列表直接给出阅读人数、分享人数、新增关注人数、送达阅读率、阅读完成率。

> 建议同时截一张单篇详情的「阅读来源」图存到 `../03-选题与成稿/` 下——
> 每 20 篇对比一次，可以看出「看一看 / 搜一搜」的推荐流量占比有没有提升。
> 这是判断「搜一搜 SEO 有没有生效」的唯一依据。
