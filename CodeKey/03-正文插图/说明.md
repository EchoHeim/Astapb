## 技术干货图优先做这几类

你的文章大量来自 `WebBlog/docs/`，原稿里的图很多是**手机拍屏或低清截图**，
转公众号时会被压得更糊。建议重做成统一风格：

| 类型 | 用途 | 说明 |
| --- | --- | --- |
| 环境搭建流程 | 每篇「从零搭建」类文章的骨架 | 竖版，5–7 步 |
| 硬件连接拓扑 | stm32mp157 / 树莓派选题 | 标出引脚与信号方向 |
| 代码前后对比 | 踩坑类文章的核心 | 左「改前」右「改后」，只留关键几行 |
| 数据图表 | Python 数据分析选题 | 用 SciencePlots 统一配色（你已有笔记） |

## 命名规范

`<栏目>-<文章简称>-<序号>.png`，如 `技术干货-扩展根分区-01.png`。

不要用时间戳命名——按文章聚合，复盘时容易找。

## 必须遵守的两条

1. **图片进仓库，不要引用外部地址。** 历史上的教训：`FPGA/verilog.md` 里 22 张图
   全部引用了 GitHub 附件地址，源仓库一变更就 22/22 全 404，且无法追回。
   正文配图一律本地化。
2. **截图要重新截，不要放大原图。** 低清图在手机上比缺图更伤观感。

## 尺寸建议

- 正文配图宽度统一 **1080 px**（公众号正文区逻辑宽度 677 px，2 倍图足够）
- 单张控制在 **500 KB 以内**
- 长图（如完整流程）可拆成 2–3 张，中间留呼吸感，不要做成一张万像素长图
