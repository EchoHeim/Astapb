# 1-Wire：只用一根数据线，真的可以完成双向通信？

> 🐵 程序小猴 · 嵌入式通信协议系列 Vol.11

---

I²C 用两根信号线已经很省了。

但工程师还不满足：

> 能不能只用一根？

于是有了 1-Wire。

很多人第一次接触它，是因为一个非常经典的温度传感器：DS18B20。

## 一、一根线怎么双向通信？

1-Wire 总线通常使用：

``` text
DATA + GND
```

数据线通过上拉保持高电平。

主机和从机通过在特定时间窗口内拉低总线完成通信。

所以关键不是单纯看高低电平，而是：

**拉低了多久、什么时候释放。**

## 二、通信从 Reset 开始

典型流程：

``` text
Master Reset
     ↓
Slave Presence
     ↓
ROM Command
     ↓
Function Command
     ↓
Data
```

主机先发复位脉冲。

从机再通过 Presence Pulse 告诉主机：

> "我在线。"

## 三、时间槽是核心

1-Wire 的 bit 并不是像 UART 那样完全依赖固定起始位连续采样。

读写都有规定的 Time Slot。

例如主机在某个时间窗口拉低，然后根据持续时间表达 0 或 1。

因此软件模拟 1-Wire 时：

``` text
delay_us()
```

的准确性非常重要。

## 四、为什么一条线上能挂多个器件？

很多 1-Wire 器件拥有唯一 ROM ID。

因此一根总线上可以存在多个节点，再通过 ROM 命令选择具体器件。

这对于大量低速传感节点很方便。

## 五、寄生供电是什么？

某些 1-Wire 设备可以从数据线获取能量。

这意味着某些场景甚至可以减少独立供电线。

但寄生供电也会带来驱动能力、强上拉和时序方面的额外要求。

## 六、它适合什么，不适合什么？

适合：

-   温度传感；
-   唯一身份识别；
-   低速节点；
-   引脚资源紧张。

不适合：

-   大数据量；
-   高速实时通信；
-   高带宽设备。

## 七、软件模拟时最怕中断

假设你正在精确控制一个几十微秒的时序窗口：

``` text
拉低
delay
释放
采样
```

突然进了一个耗时中断。

时序就可能直接错掉。

所以 bit-bang 驱动需要认真考虑临界区、定时器和系统实时性。

---

## “一根线”为什么仍然需要时序

以温度器件为例，主机先发复位脉冲并等待存在脉冲，再选择目标 ROM，发送功能命令，最后在严格的读写时隙里交换数据。多器件共享总线时，ROM ID 才能区分对象。线路通常还需要地线和上拉；所谓一线指一根数据线，并不意味着系统只接一根导线。

寄生供电模式下，温度转换等操作可能需要强上拉，普通弱上拉不一定能提供足够电流。长线、支线与大电容会拉慢上升沿；“扫描不到器件”先检查复位/存在时隙、电源方式、上拉和波形，再查软件命令。

## 写在最后

1-Wire 是一个很典型的工程取舍：

**用更严格的软件时序，换更少的硬件连线。**
