# Ethernet 详解：嵌入式设备插上网线以后，到底经历了什么？

> 🐵 程序小猴 · 嵌入式通信协议系列 Vol.09

---

UART、SPI、I²C 更多是在"设备之间通信"。

Ethernet 开始进入另一个世界：

**网络。**

一台 MCU
插上网线以后，它不仅要面对另一个设备，而可能面对整个局域网甚至互联网。

## 一、MCU 做以太网通常需要什么？

典型结构：

``` text
MCU
 │
MAC
 │
MII/RMII/RGMII
 │
PHY
 │
Transformer
 │
RJ45
 │
Network
```

MAC 和 PHY 是两个经常被初学者混淆的概念。

简单理解：

-   MAC 更偏数字协议处理；
-   PHY 负责真正的物理层收发。

## 二、插上网线并不等于能 TCP 通信

网络协议是分层的。

可以粗略理解：

``` text
Application
   ↓
TCP / UDP
   ↓
IP
   ↓
Ethernet
   ↓
PHY
```

如果使用 lwIP 之类协议栈，大量 TCP/IP 工作已经由协议栈完成。

## 三、MAC 地址和 IP 地址不是一回事

MAC 地址用于链路层。

IP 地址用于网络层。

局域网通信时，经常还需要 ARP 来解决：

> 我知道对方 IP，但它的 MAC 是多少？

于是才有：

``` text
ARP Request
ARP Reply
```

## 四、TCP 和 UDP 怎么选？

### TCP

特点：

-   面向连接；
-   有序；
-   重传；
-   可靠。

适合配置、文件、可靠业务数据。

### UDP

特点：

-   无连接；
-   开销小；
-   不保证到达；
-   不保证顺序。

适合实时状态、广播、某些控制和流式场景。

不是 TCP 一定比 UDP 好。

关键还是业务需求。

## 五、工业领域为什么越来越喜欢 Ethernet？

因为数据量越来越大。

传统串行总线可能只传：

``` text
温度 = 32.5℃
```

现代设备可能要传：

-   视觉结果；
-   大量检测数据；
-   日志；
-   配方；
-   固件；
-   实时状态；
-   MES 数据。

百兆、千兆 Ethernet 的带宽优势非常明显。

## 六、Ethernet 不等于实时工业以太网

普通 TCP/IP 网络和 EtherCAT、PROFINET 等实时工业网络不是一回事。

工业实时系统更关心：

``` text
确定性
同步
抖动
周期
```

所以不能简单认为：

> "都是网线，应该差不多。"

## 七、嵌入式 Ethernet 常见问题

### PHY Link 不起来

检查：

-   PHY 地址；
-   MDC/MDIO；
-   Reset；
-   参考时钟；
-   Auto-Negotiation；
-   网口磁性器件。

### 能 Link 但 Ping 不通

继续检查：

-   MAC；
-   IP；
-   Netmask；
-   ARP；
-   协议栈；
-   Cache/DMA。

### 偶尔丢包

进一步检查：

-   DMA Descriptor；
-   Buffer；
-   Cache 一致性；
-   中断处理；
-   网络拥塞；
-   应用层处理速度。

## 八、Wireshark 是网络调试神器

UART 有逻辑分析仪。

Ethernet 则有 Wireshark。

它可以直接看到：

``` text
ARP
ICMP
TCP SYN
TCP ACK
UDP
HTTP
Modbus TCP
```

很多网络问题，不抓包只看代码，会非常痛苦。

## 从网口灯亮到应用收包，中间隔了几层

网口灯亮通常只能说明物理链路建立；下一步看 PHY 协商速率与双工、MAC 地址和收发统计，再看 IP 地址、子网、ARP，最后检查 UDP/TCP 端口和应用协议。能 ping 通不等于应用帧解析正确；TCP 是连续字节流，应用必须自己定义消息长度或分隔方式，不能假定一次 `recv` 恰好对应一次发送。

例如 MCU 每 10 ms 上传检测结果，先计算数据量和允许延迟，再选 UDP、TCP 或现成工业协议；控制命令需要序号、超时和幂等处理。抓包时同时保存设备和 PC 的时间戳，并检查丢包、重传和交换机配置。

## 写在最后

Ethernet 把嵌入式设备从"板子之间传几个字节"，带进了真正的网络系统。

掌握它以后，你会发现很多问题已经不再只是 MCU 外设问题，而是：

**协议栈、操作系统、网络和应用架构问题。**
