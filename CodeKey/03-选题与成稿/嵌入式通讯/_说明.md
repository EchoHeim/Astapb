## 发布包：每期一个文件夹，开箱即用

一个发布包里固定有这些：

| 文件 | 说明 |
| --- | --- |
| `封面.png` | 900×383，消息列表用，主标题压在中央安全区 |
| `引导-系列导航-NN.png` | 750×140，文首署名条下方，标 VOL 号和进度 |
| `<原稿名>-<序号>-<内容>.png` | 750 宽正文图，1~2 张 |
| `_本期说明.md` | 标题、发布方式、原稿来源、装配顺序、待办清单 |
| `文章.md` / `_待写.md` | 已成稿的放文章，未写的放占位 |

### 装配顺序（每期一样）

```
封面 900×383
→ 文首署名条 750×120（全号通用，在 02-样式素材/封面与版式模板/）
→ 引导-系列导航-NN 750×140
→ 正文 + 正文图（结构图在前，排查图在后）
→ 引导-2-排查表钩子 750×118（放在排查表前一节）
→ 排查顺序表
→ 引导-3-文末收尾 750×176
→ 往期精选 / 互动 / 三连图 750×163（全号通用）
```

**宽度一律 750。** 窄一像素就会在正文里居中露出白边。

## 生成脚本

配图和封面都是代码渲染，不是 AI 生图（位序画反会让人烧板子）。

```bash
# 正文图（28 张）—— 改完需手动分发到各期
node "CodeKey/02-样式素材/封面与版式模板/_src/tech-figures/build.mjs"
"C:/Users/Lodge/AppData/Local/hermes/hermes-agent/venv/Scripts/python.exe" \
  "CodeKey/02-样式素材/封面与版式模板/_src/tech-figures/crop.py"

# 封面（14 张）—— 直接写进各期的 封面.png
node "CodeKey/02-样式素材/封面与版式模板/_src/covers/build-covers.mjs"

# 引导图（16 张）—— 导航图直接写进各期，钩子/收尾写进 _通用/
node "CodeKey/02-样式素材/封面与版式模板/_src/covers/build-guides.mjs"
```

封面和引导图两个脚本都按**发布包目录的日期排序**与数组下标对应，所以**增删期次时
要同步改脚本里的 `COVERS` / `TITLES` 数组**，否则图会串位。

## 三条硬规则

1. **不要直接拿原稿发。** 原稿是知识体系（按协议分类），标题写成「XX 详解」搜不到人。
   每期必须改造成故障入口，标题在 `_本期说明.md` 里已经定好了。
2. **每期必须补一手经历。** 原稿最大的短板是一处现场经历都没有，而这是唯一抄不走的部分。
3. **技术事实以厂商手册为准，不以原稿为准。** 已核对过的红线见 `_系列规划.md` 第 7 节。
