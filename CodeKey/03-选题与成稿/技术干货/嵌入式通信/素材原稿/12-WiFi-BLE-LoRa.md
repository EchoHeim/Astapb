# Wi-Fi、BLE、LoRa 怎么选？嵌入式无线通信一次讲清

> 🐵 程序小猴 · 嵌入式通信协议系列 Vol.12

---

项目要加无线功能时，经常会听到三个名字：

**Wi-Fi、Bluetooth Low Energy、LoRa。**

然后需求一句话：

> "我们做个无线通信吧。"

问题是，这三种方案虽然都没有线，解决的却不是同一种问题。

## 一、先看三个完全不同的需求

### 场景 A：设备要接入局域网

需要：

-   手机访问；
-   TCP/IP；
-   MQTT；
-   OTA；
-   较大数据量。

首先想到 Wi-Fi。

### 场景 B：一个电池传感器要和手机通信

要求：

-   功耗低；
-   手机直接连接；
-   数据量不大。

BLE 很合适。

### 场景 C：农田里几公里外传一个温湿度

要求：

-   距离远；
-   数据很少；
-   电池供电。

这时 LoRa 的优势开始出现。

## 二、Wi-Fi：速度和网络能力

Wi-Fi 最大的优势是：

**它天然靠近 IP 网络。**

设备连接 AP 后，可以比较自然地使用：

``` text
TCP
UDP
HTTP
MQTT
WebSocket
```

适合：

-   智能家居；
-   工业网关；
-   摄像设备；
-   OTA；
-   云端连接。

代价是功耗通常高于 BLE 和 LoRa。

## 三、BLE：重点不是"蓝牙"，而是 Low Energy

BLE 特别适合：

``` text
手机 ↔ 低功耗设备
```

常见应用：

-   手环；
-   传感器；
-   Beacon；
-   配置设备；
-   小型 IoT。

BLE 中经常会遇到：

``` text
Service
Characteristic
UUID
GATT
```

可以简单理解为：

> 设备把自己的数据组织成一组可发现、可读写、可通知的属性。

## 四、LoRa：用速度换距离

LoRa 最鲜明的特点是：

**远距离、低速率、低功耗。**

所以不要拿它和 Wi-Fi 比下载速度。

它们目标完全不同。

LoRa 更适合：

``` text
几分钟上传一次传感器数据
```

而不是：

``` text
实时传输视频
```

## 五、放在一起看

  项目       Wi-Fi      BLE              LoRa
  ---------- ---------- ---------------- ---------------------
  数据速率   高         中低             低
  距离       中         短～中           很远
  功耗       较高       低               很低潜力
  手机直连   很方便     很方便           通常不直接
  IP网络     天然适合   通常需额外方案   通常需网关/上层方案
  大数据     适合       一般             不适合
  远程传感   一般       一般             很适合

## 六、无线通信还有一个隐藏问题：环境

有线通信出问题，可以拿示波器直接量。

无线通信则还会受到：

-   天线；
-   外壳；
-   安装方向；
-   墙体；
-   金属；
-   同频干扰；
-   发射功率；
-   接收灵敏度；
-   法规；

影响。

所以模块在开发板上测试 100 米，不代表装进金属机柜后还能有同样表现。

## 七、不要最后才考虑天线

这是无线产品非常容易踩的坑。

PCB 和结构设计都完成以后才说：

> "这里随便放个天线吧。"

往往已经晚了。

天线周围净空、地平面、馈线、外壳材质都会影响最终性能。

## 八、真正的选型逻辑

可以简单记：

``` text
需要高速 + 联网
        ↓
      Wi-Fi

需要手机 + 低功耗
        ↓
       BLE

需要超远距离 + 少量数据
        ↓
      LoRa
```

如果需求同时要求：

``` text
10公里
+
高清视频
+
纽扣电池用两年
```

那问题可能不是"选哪个协议"。

而是需求本身需要重新讨论。

---

## 系列结语

从 UART 的一根 TX 线，到 Ethernet 和无线网络，通信方式看起来越来越复杂。

但所有选型最终都绕不开几个问题：

``` text
传多远？
传多快？
多少节点？
多大功耗？
多强实时性？
环境有多恶劣？
成本允许多少？
软件复杂度能接受多少？
```

没有"最好的通信协议"。

只有**更适合当前系统约束的通信方案**。

而这，恰恰也是嵌入式工程最有意思的地方。

## 同一个传感器项目，三种不同答案

厂房里每秒上传较多数据、已有 Wi-Fi 覆盖，可评估 Wi-Fi，但要把漫游、断网缓存和供电算进去。手机近距离配置设备，BLE 的手机生态和较低平均功耗更合适；实际吞吐量依连接间隔、MTU、PHY 与手机系统而变。远处电池传感器偶尔上报少量数据，可以评估 LoRa，但吞吐量低，链路预算、区域频段和当地发射规则决定部署方式。

不要只看宣传的最远距离或峰值速率。列一张需求表：每天报文数量与字节数、最坏延迟、电池寿命、网关/网络覆盖、双向控制需要、现场干扰和维护成本；再在现场按目标安装高度实测丢包与功耗。
