# I²C 详解：只有两根线，怎么让一堆芯片有序聊天？

> 🐵 程序小猴 · 嵌入式通信协议系列 Vol.05

---

PCB 上经常有这样的组合：

EEPROM、RTC、温度传感器、IO 扩展芯片。

如果每个设备都像 SPI 一样单独拉片选线，引脚很快就不够用了。

I²C 的思路很漂亮：

> 大家共用 SDA 和 SCL，再通过地址区分设备。

## 一、只有两根信号线

``` text
MCU
 │
 ├── SDA ──┬── EEPROM
 │         ├── RTC
 │         └── Sensor
 │
 └── SCL ──┴────────
```

SDA：数据。

SCL：时钟。

## 二、为什么必须有上拉电阻？

I²C 常见输出结构是开漏/开集。

设备可以主动：

``` text
拉低
```

但不会主动推高。

高电平依靠上拉电阻产生。

因此：

``` text
VCC
 │
 R
 │
SDA ───────── devices
```

如果忘了上拉，波形可能根本起不来。

## 三、Start 和 Stop 很有特点

正常传输时，SDA 应该在 SCL 低电平期间变化。

特殊情况：

``` text
SCL为高时
SDA：1 → 0  = START
SDA：0 → 1  = STOP
```

这两个条件定义了一次事务的开始和结束。

## 四、地址怎么工作？

主机先发地址：

``` text
START
  ↓
Address + R/W
  ↓
ACK
```

只有地址匹配的从机回应。

因此同一条总线上可以挂多个器件。

但如果两个器件地址完全相同又无法修改，就麻烦了。

## 五、ACK 是 I²C 很关键的一环

发送 8bit 后，第 9 个时钟用于 ACK/NACK。

可以理解为：

> "刚才那个字节你收到没有？"

如果没有 ACK，可能是：

-   地址错；
-   器件没供电；
-   接线错；
-   时序错；
-   器件忙；
-   总线异常。

## 六、Repeated Start 是干什么的？

读取很多寄存器型器件时，经常看到：

``` text
START
Device Addr + W
Register Addr
REPEATED START
Device Addr + R
Data
STOP
```

意思是先告诉设备"我要访问哪个寄存器"，然后不释放总线，直接切换到读取。

## 七、I²C 为什么速度不能无限提高？

因为高电平是通过上拉电阻给总线电容充电形成的。

总线越长、设备越多：

``` text
Cbus ↑
```

上升沿就越慢。

因此上拉阻值不是"随便放个 10k 就完事"。

需要结合：

-   总线电容；
-   工作电压；
-   速率；
-   器件灌电流能力；

一起考虑。

## 八、总线被拉死怎么办？

I²C 工程里很经典的问题：

``` text
SDA 一直为 0
```

例如 MCU 在一次通信中途复位，从机还认为事务没有结束。

常见恢复思路是：

``` text
手动输出若干个 SCL
→ 尝试让从机状态机继续运行
→ 产生 STOP
→ 重新初始化 I²C
```

因此成熟产品最好考虑 **Bus
Recovery**，而不是只在实验室里验证一次能通信。

## 九、I²C 和 SPI 怎么选？

简单比较：

  项目         I²C          SPI
  ------------ ------------ ------------
  信号线       少           多
  多设备       很方便       需要更多CS
  速度         中低速为主   通常更高
  全双工       否           可以
  协议复杂度   稍高         简单
  PCB板内      非常适合     非常适合

如果是 EEPROM、RTC、配置芯片、小传感器，我通常先想到 I²C。

高速 ADC、Flash、大量数据交换，则更容易想到 SPI。

## 工程实战：读 EEPROM 一个寄存器

假设 7 位器件地址为 `0x50`，目标内部地址 `0x2A`：`START → 0x50+W → ACK → 0x2A → ACK → REPEATED START → 0x50+R → ACK → 读数据 → NACK → STOP`。在总线上，地址加读写位形成第一个字节：写为 `0xA0`，读为 `0xA1`。资料里写 `0x50` 和 `0xA0` 可能指同一器件的两种地址表示，写驱动前先弄清 API 要求 7 位地址还是左移后的值。

SDA/SCL 都要经上拉形成高电平，器件只能主动拉低。上拉太弱，上升沿慢；太强，下拉电流增大。结合总线电容、目标速率和器件灌电流能力选值。ACK 出现在每个 8 位字节后的第 9 个时钟：主机读最后一个字节时发 NACK，表示不再继续读取。

若总线一直被拉低，先区分是 SDA 还是 SCL：SCL 被拉低可能是时钟延展或故障；SDA 被拉低可能是从机停在发送途中。在符合器件手册的前提下尝试恢复时钟并发 STOP，仍失败再复位外设或断电。切勿把所有 NACK 一律解释为器件损坏，还可能是地址表示、器件忙、内部地址位宽或电源时序问题。
