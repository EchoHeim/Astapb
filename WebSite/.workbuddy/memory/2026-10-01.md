### 修复的坑
1. **主题闪白 / 半应用主题**：`--bg` 只在 `[data-theme="dark"]` 里声明会导致两个问题——
   (a) 深色下根元素背景在按需读取样式表的分块渲染时先绘出浅色底，闪白；
   (b) 若某条消息的样式快照缺了 `[data-theme="dark"]` 块，就会出现「浅色面板 + 深色文字」的不可读态。
   解法：`html` 基础规则上写 `background-color:var(--bg)`，深色块只改变量、不再改根元素背景。
2. 截图的 `--user-data-dir` 必须每次换新目录，否则 Chrome 会复用上一个进程的实例，
   `--screenshot` 静默不生效（表现为「图片没生成」而不是报错）。
3. 第一次截图失败是因为把 HTML 写在了项目根、却从 `.workbuddy/_ref/` 取 `file://` URL
   → `net::ERR_FILE_NOT_FOUND`。截图前先 `cp` 到同一目录。

## 导航站：分类折叠默认可见数 6 → 8

**改动**：`src/data/categories.ts` —— 23 个分类的 `visible` 全部 `6` → `8`（一行 `replace_all`），
并把文件头那段「`visible: 6` 对应旧代码 `createItem(val, div, 6)`」的注释改写成
「默认展示条数，目前统一为 8，单个分类可单独调」。**只动了这一个文件。**

**为什么改一个数字就够**：折叠机制是数据驱动的，链条自洽——
`visible` → `render.ts` 写进内联 `--visible` → `components.css` 的
`height: calc(12rem + var(--row-h) * var(--visible))` 算卡片高，
同时 `render.ts` 给第 `visible` 条打 `.clamp-end`（渐变遮罩 + `mouseenter` 展开）。
**列宽/行高都不用动**：7 列 × 13rem 的网格里 `--col-w` 由最长站名决定，
多两行只影响纵向高度，不影响横向。

**验证**（无头 Chrome + CDP，实测而非目测）：
- 23 个分类 `--visible` 全是 8，卡片统一 459px（= 12rem + 2.6rem×8）；
  条目 ≥8 的分类实测可见整 8 条，条目不足 8 的 7 个分类（工具/网络/电影/搜索/财经/软件/Git收藏）本来就全显示。
- 折叠标记落在 index 7（第 8 条）✓；`mouseenter` 后 class → `item change`、`overflow: hidden` → `visible` ✓；
  `mouseleave` 收回 ✓；过滤态 `is-filtering` 下铺开 ✓。

**本轮踩的环境坑（都在本文件下方的坑清单里已记，此处是复现细节）**：
1. **`node_modules` 不存在**，得先 `npm install`（`tsc` / `vite` 都缺）。
   `npm run build` 里 `tsc` 报「不是内部或外部命令」是 PATH 问题，走 `./node_modules/.bin/` 即可。
2. **`http_proxy=http://127.0.0.1:13811` 会劫持 localhost**：curl 打本机服务回 **502**，
   无头 Chrome 直接开本机地址也是连接错误页。
   解：Chrome 加 `--proxy-server=direct:// --proxy-bypass-list=*`，
   并把子进程 env 里的 `HTTP_PROXY`/`HTTPS_PROXY`（大小写两套）清空；
   curl 调试用 `--noproxy '*'`。
3. **后台起的静态服务会跨命令消失**：`curl` 前一刻 200、下一刻 000，日志里只有一条早先的 200。
   最终解法是**把静态服务写在同一个 node 进程里**（起服务 → 拉 Chrome → 量 → 关），不再跨命令。
4. **自建静态服务别给所有 404 兜底回 index.html**：资源缺失时模块脚本会拿到 `text/html`
   被执行 MIME 校验拦掉，表现是**白屏且无报错**（只有一条 MIME 的 console error）。
   正确做法：只有根路径 / 无扩展名的路径才回退，带扩展名的真 404。
   另外产物资源引用带 `/aa/` 前缀（vite base），服务端要先剥掉再落盘找文件。
