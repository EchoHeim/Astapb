# 2026-11-16

## 网址导航站体检 + P0/P1 改造

lodge 让分析「作为网址导航有什么问题」，给了逐项实测（1440/390 两视口渲染 + 296 条数据核对 + 8 个搜索意图 + 死链探测）。结论：骨架好，问题在内容与检索。随后按建议做了 P0 + P1。

### P0（数据与数字）

- **数码推荐位三字段互不相干**：名字「果壳网」、链接 `ghxi.com`（实测 title 是「果核剥壳」）、图标 Pinterest。改成 果壳 / `guokr.com` / `header/guokr.png`（App Store 512 图，缩放 200）。
- **四个企鹅推荐位换掉**：论坛→吾爱破解（`52pojie`）、工具→iconfont（`iconfont`）、其他→天眼查（`tianyancha`）、网络→Cloudflare（`cloudflare`，原名「Cloud Flare」拼错）。三个站点提成推荐位后从 `sites` 删除（按既有规矩），`TOTAL_SITES` 296 → 293。
- 新图标来源：果壳用 iTunes 512 app icon；iconfont 用站点 `apple-touch-icon` 114 PNG；52pojie 用 `apple-touch-icon.png` 180；天眼查用 `icon-hires-192x192.png`；Cloudflare 只有 99×96 的 ICO，补成 100×100。统一 RGBA + LANCZOS。
- **计数不再手写**：`index.html` 用 `{{SITE_COUNT}}` / `{{CATEGORY_COUNT}}`，`vite.config.ts` 加 `transformIndexHtml` 插件注入（`replaceAll` 在 es2020 lib 下编译失败，改正则）。README 的三处数字改成 293，并在 `verify-icons.mjs` 里加「README 的 N 个分类 / M 个条目必须与数据一致」的硬校验（只认成对写法，否则会误伤「原有 17 个分类」这类叙述）。

### P1（检索）

- `Site.tags?: string[]` + `Category.aliases?: string[]`，293 条里 292 条写了标签（Google Trends 是多行条目，单独补）。
- `filter.ts` 重写：`tokenize()` 导出，供高亮复用；单字词命中分类名/别名 → 整格放出来；多字词走逐站匹配（干草堆 = 分类**名** + 站名 + 主机 + tags，**不含别名** —— 混进来会让「设计 字体」把 28 条全命中）。
- `dom.ts highlight()` 改成收 `string[]`：每个词找全部命中、排序合并重叠区间再切分。
- 实测：电子书 0→11、下载 0→40、ios 0→4、苹果 0→2、设计 字体 0→3、壁纸 0→14、zhihu 2（此前 2 但零高亮）。
- **「还有 N 条」徽标**：`.more` 按钮挂在 `section` 上（不能放 `.wrap` —— 展开时 wrap 变定位元素，徽标会跟着跑到列表末尾掉出视口）。点开/收起、`aria-expanded` 同步、pinned 后鼠标移开不收起。
- 折叠区打 `inert`：实测 86 条不可见链接退出 tab 序，展开释放。同时把 `.clamp-end::after` 从「0.5→1.0 整行压暗」改成「40% 以下才渐入」，第 8 条不再像禁用态。
