## 三层职责与可信度

理解这套结构的关键是分清**三层谁负责什么**：

| 层 | 路径 | 谁写 | 可信度 |
| --- | --- | --- | --- |
| **原始件** | `../尚德机构-考研/` | 机构（人） | 唯一事实来源，只读 |
| **全文层** | `markdown/` | 机器自动转换 | 有抽取误差，**未经人工校对**，关键结论请核原件 |
| **编译层** | `wiki/` | LLM 编译维护 | 摘要与索引可信；**LLM 综合推理部分已显式标注** |

每份 `markdown/` 全文页都带 front-matter，标明来源路径、页数、文字层状况与转换状态；
正文中每个 PDF 页都写入了 `<!-- page N -->` 锚点，**便于回查原件对应页**。

## 如何继续维护

本知识库遵循 Karpathy 的 LLM Wiki 模式：**人负责投喂与提问，LLM 负责编译与维护**。三个操作：

- **Ingest（灌入）**：新资料放进 `../尚德机构-考研/` 对应目录 → 重新转换 → 补摘要页 → 更新受影响的概念/主题页 → 更新 index 与 log
- **Query（提问）**：直接问，LLM 读 `wiki/index.md` 定位页面后综合作答并附引用；**有价值的回答会回填为新的主题页**
- **Lint（巡检）**：定期检查矛盾结论、过时说法、孤立页面、缺失引用

规范细节见 [[WIKI-SCHEMA]]。

## 本次建立的技术记录

- **PDF 抽取**：`pdfplumber` 逐页处理，**保留原文换行**，仅依据相邻行垂直间距插入空行来还原段落与表格块。
  经三份样本对比验证：跨行拼接会把幻灯片里的并列文本框、表格列粘连成长串，**劣化明显**，故不做文本接合。
- **DOCX / PPTX**：`markitdown`（mammoth / python-pptx）。
- **页锚点**：每个 PDF 页写入 `<!-- page N -->`，与原件页码一一对应。
- 转换工具安装在隔离环境 `~/.workbuddy/binaries/python/envs/default`，未污染系统环境。

完整变更记录见 [[wiki/log]]。
