## 追加：合集主页配置 + 搜一搜规则核实（同日 21:37）

用户发来公众号主页截图，问「如何让合集显示在主页」。查证后确认了平台规则，并顺带发现三件更要紧的事。

### 直接答案
**合集创建 ≠ 主页显示。** 必须回到合集页面上方的 `账号主页合集配置 → 编辑 → 勾选 → 确定`，
**只有在这里勾选过的合集才会出现在主页**（漏掉这步主页一个都不显示）。最多配 10 个，建议只挂 3~4 个。
其余要点：合集只能在**电脑端**创建；一篇最多进 5 个合集；建议开启「连续阅读」（文章底部出现上一篇/下一篇，
对搜索来的新读者尤其值钱）；合集有利于搜一搜抓取账号内容。

### 顺带发现的三个问题（都要修）
1. **原创声明只开了 1/3**：主页显示「56 篇原创内容」，而累计已发表 177 篇。
   搜一搜官方口径：**内容相同时优先展示「声明原创」的文章** → 这是纯白送的损失，从下一篇起每篇都勾。
2. **后台「搜索分析」模块完全没在用**：`数据分析 → 搜索分析`可看 TOP 查询词 + 曝光 + 点击 + **自己的排名**。
   这是本号唯一能直接看到「读者在搜什么、我排第几」的地方。
   用法：**筛排名 5~15 的潜力词，回去给旧文补标题关键词与段落，性价比高于新写一篇。**
3. **简介不含任何可搜领域词**：主页实际显示「好软件，不私藏。认真折腾，快乐分享！🐵」。
   搜一搜把账号名称/简介/垂直度算进账号权威度 → 建议改成「折腾 Linux 和嵌入式，实测好用的软件与工具。好软件，不私藏 🐵」。

### 另一个重要修正：只发布模式的风险被证实
公开资料对搜一搜爬虫的描述是「定期遍历**已群发**的文章」，暗示「只发布」的内容收录可能不如群发。
→ 已在方案里把 7 天验证的做法写细：**复制完整标题去搜**（搜不到＝未收录；搜得到但搜关键词搜不到＝已收录、排名靠后）。
如果连完整标题都搜不到，「只发布」玩法在本号不成立，要退回群发模式。

## 追加：板块架构定案（同日 21:54）

用户提议把公众号划成 5 个板块：AI日报 / 实用软件工具分享 / 历史人物志 / 音乐演唱会现场（配视频号）/ 小说读后感悟随笔。

### 结论：只有 2 个站得住，收敛为「1 主力 + 1 维持 + 1 储备」
| 板块 | 处置 |
| --- | --- |
| **实用软件分享** | ✅ 主力，群发，吃掉大部分产能（数据：7篇=378阅读，占83%） |
| **AI 日报** | ✅ 保留但降级：只发布不群发，只报能搜的条目 |
| **技术干货**（Linux/嵌入式/Python） | ⏸ 储备。**分界**：具体问题实操文（树莓派扩容/udev/Samba）属主力；纯知识体系类才归储备 |
| 历史人物志 | ❌ 否决 |
| 音乐演唱会现场 | ❌ 不放公众号，改由**视频号**承接 |
| 小说读后感悟随笔 | ❌ 否决 |

### 否决的核心机制（关键论据，已写入方案第 5 节）
**搜一搜的「账号权威度」约占排序权重 25%，其中含「内容垂直度」。** 号横跨 4 个不相关领域 → 算法无法打标签 → **每个领域排名都上不去**。对 69.6% 靠搜索的账号这是最贵代价。
再加油：227 粉 ÷ 5 板块 ≈ 每板块约 45 人感兴趣；非搜索型板块实测只有 8 阅读（星动之夜）。
「板块」的落地形式就是**合集**，而主页建议只挂 3~4 个 → 板块数本就不该超过 3~4。

### 给出的建设性替代：**交叉，不要平行**
兴趣 × 主业 交叉成选题，既满足兴趣又留在赛道内、自带搜索词、有一手经历：
- 历史人物 →「用 Obsidian 建三国人物关系图谱」「用 Python 统计二十四史人物词频」
- 音乐现场 →「演唱会手机录音怎么救回来：Audacity 降噪实测」「用 ffmpeg 批量剪辑现场视频」
- 小说随笔 →「用 Calibre 管理并转换 500 本电子书」「把阅读器笔记同步进 Obsidian」
