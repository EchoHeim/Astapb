### 关键技术决策（有实测依据，勿凭直觉推翻）
1. **PDF 抽取不做跨行拼接**。样本三路对比：全量 reflow 会把幻灯片并列文本框、
   表格列粘成长串（如「得分依据分数占比得分要求…」），**劣化明显**。
   最终方案 = `pdfplumber.extract_text_lines()` **保留原文换行**，
   仅按相邻行垂直间距（> 中位行高 × 0.85）**插入空行**还原段落/表格块。
2. **页锚点**：每页写 `<!-- page N -->` + `### 第 N 页`，便于回查原件。
3. **CID 乱码检测**：子集化字体（`DengXian-Regular` / `Identity-H`）ToUnicode 失效时，
   抽取结果为 `(cid:28)`。判定阈值 `cid_tokens>=30 且 占比>=1.5%`。
   实测 `pdfplumber`/`pdfminer`/`pypdfium2` **三个后端都救不回来**，只能 OCR。
   受影响：`12月冲刺学习计划.pdf`（675 个 cid）。
4. **先探测后转换会误判**。抽前 3 页统计字符密度的初判（77可提取/49稀疏/8扫描）
   在 `3MBA英语春笋班冠词.pdf`（前 3 页是图片版面）上把可用文件误判为扫描件——
   全量转换实际得到 10,545 字符。**判定文本层必须全量抽取，抽样只能筛「明显扫描件」。**
5. **近似重复要用归一化正文比对**。SHA-256 只能查字节级重复；
   三个「作文模板」文件字节不同、正文归一化后相似度 1.0（同一文档多次导出）。

- `【密训资料】管理类联考数学.pdf` p3：原页有 $a^m·a^n=a^{m+n}$、$\frac1{\sqrt3-\sqrt2}=\sqrt3+\sqrt2$；

### 一个必须记住的判据
**`conversion_status: ok` 只代表「抽到了可读文本」，不代表「内容完整」。**
整页图片有两种性质：① 冗余栅格化（文字层已捕获，图片是重复渲染）；
② 唯一载体（图表/思维导图/答题卡/公式排版，内容只在图里）。
两者在面积审计上长得一样，**必须渲染原页目视确认**才能区分。

### 关于删除的结论（重要，别被「省空间」误导）
149 份原件**全部已 git 跟踪**（`git ls-files` 149 条命中）→
**删工作区副本不减仓库体积**（blob 仍在 `.git` 历史 356.8 MB），只丢失本地唯一可读原件。
真想瘦身只能 `git filter-repo` 重写历史 —— 独立且破坏性的操作，别和「删文件」混为一谈。

## 第八轮：「渲染成 HTML 能否保证信息不丢」实测

用户问：不转 Markdown，改成渲染 HTML，是否可保证内容不丢失。做了完整实测，
新增 `wiki/topics/转换格式方案对比.md` 与 `_review/html-方案对比.html`。

### 三条路线的确切得失（实测，非推测）
| 路线 | 视觉 | 可搜索 | 依赖本机字体 | 全库体积 |
|---|---|---|---|---|
| A 栅格化（pypdfium2 → `<img>`） | ✅ | ❌ | — | 1.15×≈127MB / 2.0×≈341MB |
| B 定位文字（PyMuPDF `get_text("html")`） | ✅ 多数 | ✅ | ⚠️ 是 | ≈286MB |
| C B + 内嵌子集字体 | 预期✅ | ✅ | ❌ | 略大 |

**「HTML 省空间」不成立**：除低清栅格（换来清晰度损失）外，B/C 都比原件 319MB 更大。

### 最重要的翻车与纠正（值得记）
我一度得出「C 路线能救编码损坏件」的结论，**并已把它写进报告**。深挖后推翻：

1. 抽出的 8 个子集字体**全部没有 `cmap` 表**（只有 `cvt fpgm glyf head hhea hmtx loca maxp prep`）。
   Identity-H 靠 CID 直接当字形索引用，PDF 阅读器不需要 cmap；
   **但浏览器走 Unicode 路径，没有 cmap 什么都画不出来** → 单纯 `@font-face` 会失效。
2. 我给字体合成「码位 = 字形序号」的 cmap，然后**用 PIL/FreeType 逐码位单独渲染**（排除控制字符排版干扰）
   验证：`c=5→们`（应为「最」）、`c=4→什`（应为「后」）→ **码位 ≠ 字形序号**，映射对不上。
3. 修正后结论：要正确还原必须从 PDF 编码结构重建 CID→Unicode 映射并改写文本
   —— 这正是 `pdf2htmlEX` 存在的原因，本机没有。**该文件只能 OCR 或栅格化。**

**教训（写进技能了）**：判断「信息有没有丢」**不能只看结构匹配**（字体名对上了、表结构齐了），
**必须端到端渲染出来逐字比对**。我这次差点交付一份结论错误的报告。

### HTML 确实优于 Markdown 的地方
扫描件/整页图片型：`2022英语考试大纲 p60` 在 md 里是 0 字符，在 HTML 里是完整整页图；
`中文写作课件 p6` md 里 11 字符，HTML 里是 1920×1080 底图 + 5 张子图。

### 环境事实
- 本机**没有**任何 PDF→HTML 专业工具链：`pdf2htmlEX` / `mutool` / `pdftocairo` / Ghostscript /
  ImageMagick / LibreOffice **全部不存在**。只有 Python 方案（pypdfium2 / PyMuPDF / pdfplumber）。
- 新装到隔离环境：`pymupdf`、`fonttools`。
- `shutil.rmtree` 也被 safe-delete hook 拦截（`SAFE_DELETE_FAIL_CLOSED trash-failed`），
  Python 里删目录同样不生效，别依赖它清理旧输出。
- 验证脚本：`_scratch/audit_media.py` / `make_review.py` / `make_delete_plan.py` /
  `probe_html.py` / `make_html_compare.py` / `patch_cmap.py` / `percode_test.py` / `check_tables.py`。

## 第十六轮：WebSite 导航站重写为 Vite + TypeScript（用户要求：选合适框架重构）

### 选型结论：Vite + TypeScript，**零 UI 框架**
对比过 React / Vue / Astro，最后都没要。理由：
- 这个站是**静态 97 条链接 + 一点点过滤**，没有状态、没有路由、没有数据请求。
  引 React/Vue 等于为了几行 `filter()` 背上 40KB+ runtime 和一层构建抽象。
- Astro 是博客那边在用的，但导航站不需要内容集合、不需要 SSR，用它反而多一层依赖。
- 最终产物：**JS 22.30 KB（gzip 7.90 KB）+ CSS 5.25 KB（gzip 1.85 KB）**，
  `index.html` 3.99 KB（gzip 1.68 KB）。运行时依赖为 0。

### 先查根因，再决定怎么重写
旧站最大的问题不是"代码老"，是 **24/97（24.7%）图标静默 404**：
`create.js` 用 `switch (中文分类名)` 拼图标路径，和 `main.js` 里的数据对不上，
拼错就 `<img>` 空着，**不报错、不提示**。
所以新实现的核心设计目标是**让这类错误在构建期就炸掉**，而不是上线后肉眼发现。

### 做法
1. **图标池扁平化**：`import.meta.glob('/icon/**/*.png', …)` 一次性收集所有图标，
   建立 `文件名(去扩展名) → URL` 的映射。不再有"按分类名猜路径"这种中间层。
2. **构建期硬校验** `scripts/verify-icons.mjs`，挂在 npm `prebuild`：
   - 校验每个 icon key 都能解析到真实文件 → 解析不到直接 `exit 1`
   - 校验 URL 协议、分类 id 唯一性、默认搜索引擎存在性
   - 顺带把迁移结果打成一行摘要，每次构建都可见：
     `17 个分类 / 97 个站点（有图标 74，首字母兜底 23）`
   - **它靠 Node 22.18+ 的原生 TS type-stripping 直接 `import()` 那两个 `.ts` 数据模块**，
     所以不需要 ts-node/tsx 之类的额外依赖 —— 这条很关键，否则又要多一个 devDependency。
3. **缺图标不再"借"别家 logo**，改用**首字母色块兜底**（名字哈希 → 8 色调色板）。
   现在 74 个有真图标、23 个是刻意兜底，**没有一个是错配的品牌 logo**。
4. 语义化 + 可访问性：`<a>` 取代 `<li onclick>`、外链加 `rel="noopener"`、
   `:focus-visible` 保留（**没有**全局 `outline: 0`）、ARIA 标签。
   DOM 用自己写的 `h()` 构建，**全程不碰 `innerHTML`**（数据里带 `<` 也不会破版）。

### 新增的三个能力（用户勾选的）
| 能力 | 实现要点 |
| --- | --- |
| 站内过滤 | 匹配**站点名 + 域名**，多关键词 AND；命中分类名则放行该分类全部站点 |
| 深浅色主题 | 与博客**同一套契约**：`data-theme` + `data-theme-key` + `<head>` 内联防闪脚本 |
| 分类锚点导航 | 滚动联动高亮 |

**视觉是 1:1 保真的**，用 `getComputedStyle` 逐条对过旧值：
深色底 `#2b2b2b`、前景 `#efefef`、强调色 `#2fb388`、列表文字 `#c0c0c0`、
卡片高 386.4px（= 旧站的 `12 + 2.6 * 6`）。浅色是新加的，底色 `#fbfaf6`、强调 `#1f8f6a`。

### 锚点高亮：单锚点方案在多列布局下是错的
卡片会**多列换行**，所以"高亮第一个进入视口的分类"会把高亮打到**同一行的隔壁** ——
点"游戏"却亮"网络"。
改为**整行高亮**：把 flex 同一行（`top` 相差 1px 内）的卡片归为一组一起亮，
只用 `aria-current` 标注该行第一个，其余用 `.is-current` 类。
实测：页首亮「知识+社交+新闻+设计+图片+音乐」6 个，滚动后亮「视频+数码+购物+旅行+书籍+编程」。

### 踩坑（都是实测，别凭直觉重来）
- **`requestAnimationFrame` 在 headless `--virtual-time-budget` 下不推进**，
  而滚动高亮正好是 rAF 节流的 → 截图里高亮永远不动。
  差点当成逻辑 bug 去改。最后用 **rAF 打桩成 `setTimeout`** 跑**同一条生产代码路径**验证，
  确认逻辑本身是对的，是测试环境的问题。
- **`--force-device-scale-factor=2` 和 `--window-size=390` 一起用会骗人**：

  `left=447` 一测就明白是假象。**别把这两个参数叠着用来做移动端验收。**
- 浅色模式移动端"半屏发黑"是**错觉**：写了个最小 PNG 解码器采样像素，
  所有采样点都是 `#fbfaf6`。
  **教训：颜色判定一律走 `getComputedStyle` + 像素采样，不要肉眼看图。**
- **git 忽略规则的一个真坑**：仓库根 `.gitignore` 里写的是 `.workbuddy/_*`，

  它只匹配名为 `_` 的那个条目，匹配不到 `_shots`。
  结果 40 多个 Chrome profile 临时目录一直显示为未跟踪、差点被 `git add -A` 提交。
  改成 `.workbuddy/` 后正常。
  **验证手段：`git check-ignore -v <path>`**，它会告诉你到底是哪一行规则命中的。

## 21:05 网站导航图标统一风格

用户要求：把 `WebSite/` 里的图标全部换成统一风格，但**不改动图标的主题内容和设计元素**。

### 实现思路
不是重画一套新图标（那样会改变品牌 logo），而是做一个**归一化 pipeline**：
保留每个 logo 的原有图形与颜色，只统一画布尺寸、内边距、背景板形状。

新增脚本：
- `scripts/normalize-icon.py`：单文件处理，用 Pillow
- `scripts/normalize-icons-batch.py`：批量递归处理一个或多个目录

### 统一后的风格（circle）
- 画布 **256×256**，正方形
- 背景板为**圆形**（站点 CSS 本来就用 `border-radius: 50%` 裁圆）
- plate 颜色策略：
  - 检测图标边缘最可能的品牌背景色；如果是饱和色，**保留当 plate**
  - 如果是白/黑/灰/透明等中性背景，则抠掉背景，用 mark 的主色当 plate
  - 多色 mark（Google、Wikipedia 等）自动回落到**浅灰中性底**，避免某一种颜色喧宾夺主
  - plate 亮度钳到 [55,210]，防止在深浅主题里消失
- mark 缩放后居中，占圆直径约 70%

### 处理范围
- 处理：`icon/`（69 个）、`header/`（12 个）、`search/`（9 个） = **90 个 PNG**
- 不处理：`img/` 里的 UI 装饰（搜索框 logo、搜索图标）和 `public/favicon.png`，
