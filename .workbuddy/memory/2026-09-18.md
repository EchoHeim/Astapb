# 2026-09-18

## Astapb 仓库全面分析（只读，未改动源码）

对 D:\Personal\Astapb 做了完整结构梳理与代码审查。

**仓库定位**：个人嵌入式工程工具箱 + docsify 知识博客，GPL-3.0，
远程 EchoHeim/Astapb，部署域名 shilong.js.org，总量约 755 MB
（162 个 PDF 占大头，含考研/港股打新资料）。

**三层结构**
- `mfast` + `mfast.cfg` + `mfast_ui/`(8) + `mfast_fun/`(7)：交互式构建工具链 v1.0.6，
  bash 模块化，入口 source 全部脚本 + `do_action` 统一调度。
- `shell/`：H616 / mp157 / RPi / rootfs 四个平台的实战脚本。
- `docs/`(docsify) + `src/`(6 个 C 驱动样例) + `scripts/`(Python 报 IP) + `Records.md`。

**发现的缺陷（详见当日对话）**
1. `mfast_ui/menu_rootfs.sh` 与 `mfast_fun/fun_rootfs.sh` 重复定义 rootfs_ui/rootfs_menu，
   后者覆盖前者 → Armbian 菜单是死代码，且 UI 显示 "Armbian" 与实现 "H616" 不符。
2. 主菜单 1 走的 rootfs_menu 调用 `H616_build` / `update_all`，两者均未定义 → 必然报错。
3. `menu_rootfs.sh` 引用未定义变量 `BB4U_STATUS`、`DISPLAY_SYS_UPDATE`、函数 `back_footer`。
4. `menu_mp157.sh` UI 里的第 7、8 项（compile/clear rootfs）没有对应 case 分支。
5. `menu_RPi.sh` 第 2/3/4 项误调用 H616 的构建函数；`build_rpi`/`build_pi3_*`/`build_pi4_*` 是死代码。
6. `mp157_cpmpile_rootfs` 引用未定义变量 `PATH_SOURCE_5_4_BUSYBOX`。
7. 分层混乱：`settings.sh`（UI 性质）放在 `mfast_fun/`，`change_path`（逻辑）放在 `mfast_ui/`。
8. 配置三处分散：mfast.cfg / mfast_fun/path.sh / 硬编码 `$HOME` 路径；
   `sed -i` 直接改写 mfast.cfg 会污染版本控制。
9. `mp157_flash` 的 factory/bootfs/rootfs 三分支赋值完全相同，逻辑未实现差异。
10. `docs/index.html` 本地样式路径写成 `../css/custom.css`，正确应为 `css/custom.css`。
11. git 历史提交信息存在编码乱码（GBK/UTF-8 混用）。
12. `CatchIP.py` 的 `finally: s.close()` 在 socket 创建失败时会抛 UnboundLocalError。
13. 依赖 `dpkg-query`，非 Debian 系主机无法启动；`mfast_backup` 直接 push master。
