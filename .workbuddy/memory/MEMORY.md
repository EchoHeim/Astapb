- **★ 权威数据源是后台导出，不是仓库台账**。后台「下载数据」导出的趋势 xls 能一次拿到每日分渠道阅读 + 每日发表篇数 + 按文章归因的来源构成；单篇明细给送达人数/完读率/停留/新增关注/性别年龄地域。**别用仓库台账倒推「有没有发」**（09-20 就有一行幽灵记录：登记表里有、后台发表 0 篇）。两份 CSV 均为 **UTF-8 with BOM + CRLF**，追加时要照原样。
- **去 AI 味（humanizer v4.1）只对「散文正文」生效，固定模块是免检区**：署名条/往期精选/互动话术/三连引导/免责声明/栏目尾标的标点与措辞属家规，不套用「禁冒号、禁破折号」那套（标题里的冒号同样是账号惯例）。技术稿实测主要 AI 味就三个：破折号密度、散文里的冒号式「下定义」、「说白了」这类踩雷词。
- **润色会让篇幅变长**（散文替掉压缩过的 bullet 结构），改完必须回看字数；用户对工具实测稿的要求是「不长」，实测 1600 汉字上下是当前基线。

## 环境坑
本机 bash 无 coreutils **且无 `grep`/`cat`**，管道过滤一律 `command not found`；PowerShell 不回显 stdout，重定向还会把 UTF-8 按 GBK 解码 → **文件操作与读输出一律走 node 写文件 + Read 工具**；命令行里写正则会**被 shell 吃掉反斜杠**，一律写成 `.mjs` 文件再跑。`git config core.quotepath false`；无头 Chrome 截图见 skill `local-html-visual-verify`。
**同一文件禁止并行 Edit**（一次消息里发两个 Edit 会互相覆盖，前一次静默丢失、两次都报成功）；同文件多处修改要么串行、要么直接 Write 整份重写，改完做一次逐行 diff 校验。
**读后台导出的 .xls 用 `xlrd`**（venv 已装 2.0.2）：`sh._cell_values` **是参差不齐的**，`sh.cell_value(r,c)` 越界会抛 `IndexError`，必须包一层安全取值。趋势导出是**三块并排**的表（各块列号不同，套错会静默读到隔壁字段）。看图仍走 Pillow 裁切放大（`Add-Type` 被安全策略拦）；剪贴板图在 `C:\Users\Lodge\.workbuddy\clipboard-images\`。
