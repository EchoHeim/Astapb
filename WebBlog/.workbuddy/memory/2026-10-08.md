**★ 最大的坑：这些「图标」不是方形图标，是横向字标**
`alipay.svg` viewBox 448.5×145.5、`wechat.svg` 531.2×161.7、`QQqianbao.png` 104×30，
全是约 **3:1 的字标**（支付宝还是 `#074098` 深蓝）。第一版按 26×26 方框 + `contain` 排，
渲染出来就是三坨看不清的小糊块 —— 截图一看才发现。改成 **62×20 扁长框**才对。
连带的第二个问题：深蓝字标放在深色卡片上**直接糊掉**（对比度不足，也算 a11y 问题）。
最终解法是**图标条常态就用浅色底**（原版本来就是 `#fff` + `#ddd`），深色模式换成暖白
`#efece2` 而不是跟随 `--paper`。**这比给图标加 invert 干净**，品牌色在深浅两套里都保住了。

**别的实现要点**
- `text.png` 上下大片透明（字只占 256×66 那条）：容器给 `aspect-ratio: 256/66` +
  `object-fit: cover`，浏览器等比放大后居中裁掉透明边 —— **不用改图**就能把字铺满。
- 手写图在深色模式下要 `invert(1)`（黑墨字），图标条不用。
- 验证用了 skill `local-html-visual-verify` 的 `cdp-shot.mjs`（主题键名 `blog-theme`）。
  生产路径另用 `CDN_MAP` 把 jsDelivr 映射到本地仓库目录验了一遍，**全部 FULFILL 无 MISS**。

**★ 生产分发的真实机制（别记错）**：`src/consts.ts` 的 `ASSETS_BASE` 非 dev 值是
`https://cdn.jsdelivr.net/gh/EchoHeim/Astapb@master/WebBlog` —— 指向**主仓库**而不是
独立资源仓库。所以 `sponsor/images/` 里**新增的图（如 WePayQR.png）必须 commit + push
才会生效**，否则线上 404；而 dev 下走站内相对路径，本地看不出问题。

  （90→-60→40→-28→18→-12→9→-5→2→0）
- 收起动画是**死代码**：`is-out` 挂上后 `close()` 立刻 `hidden=true`，动画根本没播

白送 Esc / 焦点 / inert）。两个新踩的坑：
- **`<dialog>` 的 UA 样式带 `height: fit-content`**，只写 `inset:0` 会被它盖掉 → 内容贴顶不居中，
  必须显式 `height: 100dvh`。
- **遮罩不能用 SearchDialog 的 `color-mix(--ink 42%)`**：`--ink` 在深色模式下是近白 `#f0ede5`，
  会把深色页面**反过来冲成灰白**。改成两套主题各自定值（浅 `#17150f 45%` / 深 `#000 62%`）。
- 验证手法：每 40ms 采一次 `getComputedStyle(card).transform`，从 matrix3d 反解 rotateX 角度，
  直接看节拍是否等于原版 —— 比截图可靠。收起时序：opacity 保持 1 到 260ms、507ms 归零、
  **631ms 才 close()**，与原版 0.5s + 600ms 完全吻合。
